<b>Елизавета, встреча 13 ноября</b>

<blockquote>Направление определилось: сравнить, как LLM находит смысловую несогласованность при контексте из trace links и при контексте из кластеризации. Идея пока остаётся непонятной руководителю, поэтому сейчас важнее начать делать на данных, чем объяснять.</blockquote>

<b>Обсудили</b>  
• Данные: найдены наборы user stories и функциональных требований, часть из них уже со trace links. BPMN в них нет. User story может сама играть роль функционального требования.  
• Из статей Ferrari (NLP4RE) выбрана кластеризация: область изучена широко, вклад видится в сравнении двух способов собрать контекст для LLM.  
• Пример: открытый проект по очередям в медицинских учреждениях. Изменение user story не дошло до требований, и срочные пациенты попали на обычный приём. Задача работы, чтобы аналитик заметил такое до реализации.  
• Идея третьего ответа «no evidence»: одна user story может быть связана с несколькими функциональными требованиями, и ответа «согласовано / не согласовано» недостаточно.

<b>Что требует доработки</b>  
• <b>Объяснение идеи.</b> Руководителю пока неясно, что именно сравнивается, как это проверяется и какая от этого польза. Пример с очередями не принят как закрытый A11. Яснее станет на реальных данных: пара артефактов, контекст из trace links, контекст из кластеризации, ответ LLM.

<b>Решили</b>  
• Начинать делать, не дожидаясь полного объяснения: понимание придёт в процессе.  
• Сначала привести в порядок эксперимент: какие данные берутся на каждом этапе. Таксономию ошибок пока не строить. Руководитель отметил, что она может стать самостоятельным результатом.
