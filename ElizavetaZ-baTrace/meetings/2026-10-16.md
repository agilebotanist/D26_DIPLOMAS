# Елизавета Загурских — встреча 2026-10-16

**Итог:** Ядро темы сдвинулось с traceability на проверку согласованности цепочки аналитических артефактов с помощью LLM. Направление ясно, но пока непонятно, в каком домене, на каких данных и как извлекаются связи.

## Почему

- Сдвиг обоснован чтением: traceability изучена глубоко, авторы пишут, что LLM там пока хуже NLP, а по согласованности работ меньше. Там, где работы есть, датасеты сгенерированы GPT и проверены им же, что она справедливо считает странным.
- План уже содержит сильные ходы: таксономия несогласованностей (действия, объекты, субъекты), прогон тремя LLM по несколько раз, формальные проверки по семантическому представлению требований (актор, объект, условие) для простых ошибок, эксперименты с разным контекстом: пара требований или вся цепочка.
- Данных не хватает: свои кейсы банковские, и результат может не перенестись. Руководитель советует искать открытые датасеты по нескольким проектам из разных областей. Ручное внесение ID годится для своей валидации, но не для оценки.
- Домен не сужен: на вопрос, какие системы, названо «документооборот, наверное». TOGAF, BIAN, ArchiMate прочитаны, но это очень широко.

## Решения

| # | Решение | Обоснование |
|---|---------|-------------|
| Р1 | Основной фокус: согласованность между артефактами, не восстановление связей | Traceability изучена глубоко |
| Р2 | Проверять согласованность и по горизонтали (на одном уровне), и по вертикали (через уровни) | Одно представление для всего на практике невозможно: нужна интерпретация правил и связка требований, кейсов, процессов. [уточнить] |
| Р3 | Для оценки взять открытые датасеты с несколькими проектами из разных областей | На одном проекте валидации нет, и банк не должен быть единственным |
