<b>Михаил, встреча 6 ноября</b>

<blockquote>Опасение, что детерминированный инструмент всегда выигрывает, снято: работа строится как сравнение LLM без инструмента и с ним. Вклад это набор правил плюс инструмент; самообучение правил отложено.</blockquote>

<b>Обсудили</b>  
• Замеры: детерминированные правила проходят 100 из 100 тестов на известных проблемах виртуальных потоков, LLM при выборе действий из набора иногда ошибается.  
• Сомнение, есть ли смысл в LLM, если инструмент надёжнее.  
• Датасет: сейчас около девяти проблем с виртуальными потоками, не репозиториев.  
• Идея, чтобы LLM сама пополняла правила инструмента.

<b>Что требует доработки</b>  
• <b>Универсальность инструментов.</b> Инструменты миграции ограничены: где-то работают, где-то нет, LLM применима шире. Этот тезис нужно подтвердить обзором существующих детерминированных инструментов, а не принимать заранее.  
• <b>Проверка на реальных проектах.</b> Девяти проблем для вывода мало; стоит посмотреть, как подход работает на реальных проектах.  
• <b>Гипотеза выигрыша.</b> Ожидается, что с инструментом LLM работает быстрее и лучше, чем без него; это нужно показать замером.

<b>Решили</b>  
• Основная постановка: LLM без инструмента против LLM с детерминированным инструментом.  
• Вклад: набор правил для известных проблем и инструмент, ускоряющий работу LLM.  
• Пополнение правил самой LLM это отдельный вопрос о самообучении, в эту работу не входит: future work.
