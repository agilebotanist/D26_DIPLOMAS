## Суть вопроса

Какие знания о сервисах команды и прошлых ревью стоит сохранять, чтобы система ИИ-ревью могла учитывать контекст проекта и помогать предотвращать повторение ошибок?

Идея возникла из [[Automated Code Review In Practice]], где обмен знаниями и обучение названы среди преимуществ ревью. Сохранение такого контекста для ИИ — развитие этой мысли.

## Идеи

Можно исследовать сохранение сведений о сервисах, повторяющихся замечаниях и принятых в ходе ревью решениях. Возможный вариант хранения — база заметок, например в Obsidian.

- [[Может ли ИИ-ревью помогать выявлять причины повторяющихся дефектов?]] — история ревью может использоваться для поиска общих причин ошибок.
