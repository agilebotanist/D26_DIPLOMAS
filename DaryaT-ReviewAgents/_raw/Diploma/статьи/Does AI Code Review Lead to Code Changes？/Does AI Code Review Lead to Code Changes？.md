## Суть работы
Авторы исследуют использование инструментов AI-ревью на базе GitHub Actions и то, насколько часто их замечания учитываются в последующих изменениях кода.

Работа отвечает на три вопроса:

1. Как инструменты AI-ревью используются и настраиваются в GitHub-репозиториях?
2. Как часто AI-комментарии учитываются в изменениях кода по сравнению с комментариями людей?
3. Какие характеристики инструментов, комментариев и контекста разработки связаны с вероятностью учёта замечаний?

По оценке LLM-assisted framework авторов, среди комментариев к влитым PR доля учтённых AI-комментариев составила от 0,9% до 19,2% в зависимости от инструмента, а человеческих — 60% (таблица IX). Учтённым считался комментарий, если хотя бы одна содержащаяся в нём рекомендация была полностью реализована.

## Рекомендации авторов к инструментам AI-ревью

- **Привязывать комментарии к конкретным изменениям (hunk-level).** Такие замечания проще применить, чем общие комментарии к PR или файлу.
- **Поддерживать и поощрять ручной запуск.** Разработчики должны контролировать момент запуска инструмента, чтобы PR не заполнялся бесполезными комментариями.
- **Предлагать конкретные изменения кода.** Авторы выделяют многострочные блоки кода, которые часто можно скопировать и применить с минимальными усилиями.
- **Фильтровать расплывчатые комментарии до показа разработчику.** Предварительная проверка должна отсеивать предложения, по которым непонятно, что именно следует сделать. В качестве примера авторы приводят свой классификатор Stage-1.
- **Адаптировать ревью.** Учитывать опыт участника в проекте: менее опытным участникам обратная связь может принести больше пользы. Менять уровень детализации с учётом размера изменения или критичности файла.
- **Обогащать контекст LLM.** Передавать название и описание PR, сводку изменений и обратную связь пользователя.
