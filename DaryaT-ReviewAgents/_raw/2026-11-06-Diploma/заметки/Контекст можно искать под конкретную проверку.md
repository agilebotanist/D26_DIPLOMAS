## Суть концепции

В iCodeReviewer система выбирает из доступного контекста элементы кода, относящиеся к конкретному типу проблемы и связанным внешним вызовам.

Например, для проверки двойного освобождения памяти (*Double Free*) система ищет в контексте API, освобождающие память. Затем связывает найденные сущности и операции с переменными исходного фрагмента с учётом передачи аргументов при вызове функций. Полученные признаки используются при выборе специализированных проверок.

## Мои мысли

Мне интересна возможность связывать пункт чеклиста с информацией, необходимой для его проверки. Например, проверка соответствия реализации контракту API требует сопоставить код со спецификацией. Пока остаётся открытым вопрос, как автоматически находить нужный контекст и определять, достаточно ли его для вывода. Отдельное сравнение способов подбора контекста пока откладываю, чтобы сосредоточиться на содержании чеклистов и способе их выполнения.
