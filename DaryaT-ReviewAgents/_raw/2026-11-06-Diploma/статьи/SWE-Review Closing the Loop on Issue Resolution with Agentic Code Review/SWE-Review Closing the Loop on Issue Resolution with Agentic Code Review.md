## Суть работы

SWE-Review рассматривает код-ревью как часть замкнутого решения программной задачи. Ревьюер получает репозиторий, описание задачи и PR, исследует код и исполняемое окружение, затем выдаёт решение `approve` или `request-changes` и, при отклонении, структурированную диагностику с предлагаемыми исправлениями (§3, с. 3–4).

В цикле `generate → review → revise` одобренный патч сохраняют, а отклонённый возвращают исходному coding agent вместе с отзывом. В основном протоколе RRR агенту дают одну попытку доработки; отдельно авторы проверяют несколько последовательных раундов ревью и исправления (рис. 1, с. 3; §3.1, с. 4; §4.3, с. 8–9). Такая организация разделяет роли генератора патча и ревьюера, но работа не сравнивает разное число агентов.

Оценка проведена на SWE-Review-Bench: 1 384 PR для 500 задач SWE-bench Verified, полученные тремя генераторами. Измеряются завершённость отчёта, точность решения и доля задач, решённых после доработки (RRR). Агентское ревью сравнивают с однопроходным ревью по diff и фиксированному контексту; результат показывает пользу режима целиком, включая поиск контекста и проверки (§3.1–3.2, с. 4–6). Выводы ограничены функциональной корректностью AI-сгенерированных патчей и выбранными задачами, моделями, промптами и scaffold (с. 10).
