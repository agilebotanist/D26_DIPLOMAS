- **October 2026 Study: Anthropic’s Claude Opus 5.5 and OpenAI’s GPT-6-Sol Jointly Lead at a Record 73%, Breaking the Previous High of 68%**

**BURLINGTON, Mass. – October 29, 2026** – [Veracode](https://www.veracode.com/), the global leader in application risk management, today announced a jump from 56 percent to 62 percent in overall AI-generated code security, alongside a drop in vulnerabilities from 44 percent to 38 percent — the most significant improvement since the [GenAI Code Security Report](https://www.veracode.com/resources/fall-2026-genai-code-security/) series began in July 2025. Anthropic’s Claude Opus 5.5 and OpenAI’s GPT-6-Sol co-lead the rankings at 73 percent, surpassing the previous high of 68 percent set by GPT-5.5 in July 2026.

“We’ve been analysing code generated by multiple LLMs for more than a year. Until now, we have not seen a marked improvement in AI code security, despite consistently near-perfect functionality,” said Chris Wysopal, Co-founder & Chief Security Evangelist at Veracode. “This is the first time since running our study that we’ve been able to report a meaningful move on the security dial. Ten models now clear 60 percent, up from four in the last report, and the overall average has jumped six percentage points. With around half of code now generated by AI, today’s results are truly encouraging.”

**Claude Opus 5.5 and GPT-6-Sol Lead the Way**

Veracode tested 18 models across four languages (Python, C#, JavaScript, Java) and four Common Weakness Enumeration (CWE) categories (CWE-89, CWE-327, CWE-80, CWE-117). Claude Opus 5.5 and GPT-6-Sol tied at 73 percent, dethroning GPT-5.5, which led the summer 2026 snapshot at 68 percent. Anthropic and OpenAI each have models in the top seven. In July, six of 11 models sat between 50 and 53 percent; today only two remain in that band, while 10 clear 60 percent. The floor hasn’t moved, however, with the bottom still at 44–50 percent, meaning vulnerability volume still depends on model selection.

**The Improvement Has a Caveat: XSS Is Doing the Heavy Lifting**

Vulnerability type CWE-80, cross-site scripting (XSS), was the main driver of the overall gain. Despite being one of the weaker categories, XSS rose to 18 percent, in contrast to its modest uptick demonstrated in July’s analysis. This represents the single biggest shift in the dataset. Meanwhile, crypto (CWE-327) held at 87 percent, Structured Query Language (SQL) injection (CWE-89) held at 84 percent, and log injection (CWE-117) remained flat at 13 percent. The reason is structural: XSS is the easiest vulnerability to fix through pattern recognition, which is exactly how LLMs improve. Log injection requires data-flow reasoning across multiple functions, where LLMs continue to stall.

**Progress Comes at a Price**

The top-performing models carry premium compute costs. Performance also correlates with model size: large models average 55 percent versus 51 percent for small models, which reverses last year’s finding that size had “essentially no effect” on security.

“The models that produce the most secure code are the ones that cost the most to run at scale, yet they still fail on more than one in four security tasks,” Wysopal said. “The answer should never be to use the most expensive model and hope for the best. A mid-tier model at a 60 percent pass rate plus Veracode scanning is more accurate, more cost-effective, and more scalable than a frontier model at 73 percent with no verification. Organisations must look for a combination of coding model, security testing, and remediation to get the highest security outcome.”

**The Field is Splitting**

- **General models pull further ahead of coding models.** General-purpose models average 54 percent on security tasks versus 51 percent for coding-specialised models — a gap that has widened from one to three points since July.
- **Nearly four in 10 AI code tasks still produce vulnerable code.** The rate of vulnerabilities dropped from 44 to 38 percent. This is meaningful but still means roughly four in 10 tasks produced vulnerable code without security-specific guidance.
- **Java is still stuck.** Java remains the dramatic outlier at 31 percent, barely up from 30 percent in July. The gap between Java and the other three languages (Python at 64 percent, C# at 60 percent, and JavaScript at 57 percent) is still 26–33 percentage points.

**The Bottom Line**

The improvement is real but mends a small part of a larger wound. According to [Veracode’s 2026 State of Software Security report](https://www.veracode.com/resources/analyst-reports/state-of-software-security-2026/), 82 percent of organisations now carry security debt (vulnerabilities unresolved for more than a year). Moreover, 66 percent of the most dangerous, long-lived vulnerabilities come from third-party code, taking 358 days to fix on average.

“Newer LLMs are producing more code that’s both functional and secure, but that does not mean we can start blindly trusting AI-generated code,” Wysopal closed. “The most effective strategy isn’t chasing the most expensive model for marginal gains; it’s combining AI code generation with continuous, independent security verification that catches what the models miss. That approach covers the full risk surface, from first-party code to third-party dependencies.”
