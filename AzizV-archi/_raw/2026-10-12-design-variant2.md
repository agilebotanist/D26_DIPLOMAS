Оценка Принципов чистой архитектуры остается часто 
неформальным ( то есть глазками других разрабов). Такой 
принцип очень плохо масштабируется, особенно если в проекте 
много гетрогенных репозиторий 
Предложили фреймворк который на основе ИИ будет 
Анализировать кодовую базу. Ключевые отличия:  - - - - 
Связали LLM жесткими правилами(рубриками: какие 
нарушения находить; json форматом для output) 
Рубрика имела вид: Тип нарушения - какие статические 
принципы сигнализируют о нарушении.   
Вскармливали static-evidence из модуля, рубрики, и 
конфигурации ввода-вывода 
Результат ИИшки прогоняли через 3х разрабов. Если ⅔ 
консенсус.  
Метрики: - - - 
Взвешенная каппа Коэна (Cohen’s Weighted Kappa): 
Оценивает совпадение мнений для порядковых данных, 
сильнее штрафуя за грубые ошибки. 
Коэффициенты согласия Гвета (Gwet’s AC1 / AC2): 
Устойчивая к дисбалансу данных метрика согласия 
(решает парадокс каппы). 
Альфа Криппендорфа (Krippendorff’s Alpha): 
Универсальный показатель надежности для любого 
количества экспертов с поддержкой пропусков. 
- 
Точный тест Макнемара (McNemar Exact Test): Измеряет 
систематическое смещение (bias) между двумя ревьюерами по 
бинарным ответам. -  - -

Constraint decay: The Fragility of LLM Agents in Backend Code Generation- 
показали, что если LLM связать структурными ограничениями, условно 
сказать условно “Соблюдай принципы чистой архитектуры”, то ее

магии под капотом) -  
В чем смысл применять LLM в анализе нарушений чистой 
архитектуры? Почему не обычные тулзы? - 
Под обычными тулзами имеем в виду SonarQube и ArchUnit. То у первой 
проблема в том, что выдавет много False Positives, из за чего issues может стать 
свалкой (статья, вторая требует постоянного обновления и поддержки. 
Гипотизы 
1. ИИ с правильно подобранным промптом (ограничения, рубрики, контекст о 
коде) способен обнаружить не меньше количество ошибок, чем тесты на 
ArchUnit 
2. Оптимизация рубриатора (фреймворк из An Evidence-Based LLM Framework for 
Expert-Validated Clean Architecture Conformance Assessment in Enterprise 
Software Systems) добавлением динамического контекста способен увеличить 
количество TP кейсов
